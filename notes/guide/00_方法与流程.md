# 考什么、怎么准备

ML Coding ≠ LeetCode。考的是**把公式变成向量化、无 bug 的 NumPy/PyTorch 代码**，并能讲清边界条件与数值稳定性。

| 类别 | 必刷题 | 核心考点 |
|---|---|---|
| 经典 ML（纯 NumPy） | KNN、K-Means(++)、Linear/Logistic Regression、决策树/随机森林、GMM(EM)、PCA/SVD | 矩阵求导、向量化距离、收敛判断、`fit/predict` 接口 |
| DL 组件 | MHA(causal mask, KV cache)、BN/LN/RMSNorm、Conv2d/MaxPool、Dropout、LoRA | 维度变换、train/eval 差异、`register_buffer` |
| 损失与指标 | CE+Softmax、Focal、InfoNCE、AUC、IoU/GIoU/NMS、Chamfer | 数值稳定、空集/除零 |
| 采样解码 | Top-k/Top-p/Temperature、Beam Search、加权随机采样 | cumsum、排序、归一化 |

### 通用训练方法

1. **肌肉记忆**：`None/np.newaxis` 对齐维度；`@` / `np.matmul` / `einsum`；`where/argmax/argsort`/布尔掩码。
2. **数值稳定三条**：
   - `log(x)` → `log(max(x, 1e-12))`
   - `exp(x)` → 先减 `max`
   - 除法 → 分母加 `eps`（1e-8）
3. **每行注释 shape**（`# (B, H, T, dk)`），既防错，也让面试官看懂。
4. **写完自检**：有没有隐藏 for 循环？有没有 overflow / 除零 / 空集？有没有硬编码维度？
5. 平台：Deep-ML、LeetGPU、TensorTonic。写完可让 LLM 做上面第 4 条的 review。
6. **面试流程**：先复述题意并确认约定（sum 还是 mean？平方与否？batch 维？）→ 先写最直观版本 → 再主动提优化（matmul 展开、省内存）→ 讲复杂度与边界。

### 代码规范（面试时按这个写）

- 函数/方法**所有参数和返回值都写类型注解**：`np.ndarray`、`torch.Tensor`、`int`、`float`、`bool`、`Optional[...]`、`Tuple[...]`、`List[int]`。`fit` 返回 `"Self"` 写 `-> "ClassName"`（return self），`__init__` 返回 `-> None`。
- 标量指标返回 Python `float`（`float(...)`），索引返回 `int`，不要把 `np.float64` 直接丢出去。
- docstring 写清每个输入的 **shape + dtype** 和返回的 shape，例如 `P: (N, D) float`、`y: (N,) int in [0, C)`。
- 分类标签统一为 `(N,)` 非负整数；二分类标签 `{0, 1}`。
- 边界：写在 docstring 里（"k > N 时取 N"、"只有一类时返回 0.5"），并在代码里处理。
- 完整示例见 [code/ml_coding.py](../../code/ml_coding.py)，各函数的 Args/Returns 可直接对照。

### 写法风格：拆开写，别压成一行

面试官要看的是思路和可检查性，不是代码行数。

- **一行一个想法**：每个中间量起一个有意义的名字（`p_sq`、`cross`、`nearest`），行尾注释 shape。
- **一个函数只做一件事**：K-Means 拆成 `_init_centroids` / `_assign` / `_update` / `fit`；GMM 拆成 `_e_step` / `_m_step`；采样拆成 `top_k_filter` / `top_p_filter` / `softmax`。
- **先写骨架再填空**：先把类/函数名和注释写出来，让面试官看到整体设计。
- **先朴素后优化**：先写最直观的版本（广播 / 循环），说出复杂度问题后再改成 matmul 展开。
- **return 前不做运算**：先算出结果变量，再 return。
- 边界条件单独一个 `if` + 注释（空簇、k>N、只有一类），不要藏在表达式里。
